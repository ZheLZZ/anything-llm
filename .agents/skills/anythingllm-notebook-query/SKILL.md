# AnythingLLM Notebook Query

Use the AnythingLLM MCP tools to delegate both retrieval and answer generation
to a named Workspace. Return the generated answer with its source metadata.

## Required tools

Use these MCP tools:

- `anythingllm_list_notebooks`
- `anythingllm_query_notebook`

If either tool is unavailable, state that the `anythingllm_local` MCP
dependency is not connected. Do not call the API with shell commands, read
AnythingLLM storage directly, or ask the user to paste an API key.

## Workflow

1. Resolve the notebook.
   - Use an exact user-provided slug when available.
   - Use an exact name otherwise.
   - List notebooks when the target is omitted or unclear.
   - Never guess between duplicate names; require a unique slug.
2. Manage the visible AnythingLLM Thread.
   - Omit `threadSlug` on the first query in a Codex task or conversation. The
     tool creates a real Thread that is visible in the AnythingLLM UI.
   - Preserve the returned `thread.slug` and pass it as `threadSlug` only for
     intended follow-up questions in the same task, notebook, and conversation.
   - Omit `threadSlug` for a new Codex task, a new conversation, or a different
     notebook. Never reuse one Thread globally across tasks.
3. Split broad requests into focused query rounds.
   - Give each tool call one primary information need. Combine subquestions only
     when they concern the same entity and tightly related facts likely to be
     retrieved from the same source window.
   - Split checklists, multiple entities, different periods, or independent
     topics into multiple calls instead of sending one large compound question.
     Keep the user's requested order and reuse `threadSlug` when the rounds
     belong to the same conversation.
   - Make every round specific enough for vector retrieval. Repeat the relevant
     entity and topic instead of relying on vague pronouns or references such as
     "he", "that", or "what about the other one".
   - Complete all required rounds before answering the user; do not silently
     drop later questions merely because they were split.
4. Query AnythingLLM.
   - Pass the user's substantive question to `anythingllm_query_notebook`.
   - Do not begin the question with `@agent` or `/`; the tool rejects agent and
     command prefixes to keep execution in query mode.
   - If the user intentionally supplies such a prefix, explain the restriction
     and ask for a query-mode question without it. Do not silently bypass it.
5. Return the delegated answer.
   - The MCP text result contains only `answer`; return it directly and preserve
     its meaning. Limit changes to necessary formatting or a transformation the
     user explicitly requested.
   - The tool removes a leading `<think>...</think>` block before returning the
     answer. Do not retrieve or expose hidden reasoning from another channel.
   - When `hasSources` is true, list the distinct source documents and available
     chunk positions from compact `structuredContent` metadata. Raw source text
     is intentionally excluded to keep the task context bounded. Preserve
     material qualifiers and do not invent locators.
   - When `hasSources` is false, return the AnythingLLM refusal or source-free
     response and state that no source-backed answer was produced. Do not add an
     answer from general knowledge.
   - Do not automatically run raw retrieval to second-guess the generated
     answer. Use the retrieval skill only when the user asks to inspect evidence
     or exact passages.

## Errors and boundaries

- For `NOTEBOOK_NOT_FOUND`, list available notebooks or request the intended
  one.
- For `AMBIGUOUS_NOTEBOOK`, present the candidate slugs and do not choose
  silently.
- For HTTP 403 or missing-key errors, state that `ANYTHINGLLM_API_KEY` is not
  available to the MCP process.
- For connection errors, verify that local AnythingLLM is running before
  changing the question.
- Treat query calls as non-idempotent: AnythingLLM persists visible Thread chat
  history.
- The Workspace model may be local or remote. Do not claim the query remained
  on-device unless the configured provider has been verified.
- Never expose API credentials, embedding vectors, or unnecessary source text.
